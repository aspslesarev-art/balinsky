# Шаблон страницы застройщика (хендофф Urban Escape) — чек-лист данных

Прототип: `/admin/preview/zastrojshhik/[slug]` (под админ-логином, `noindex`, публичных
ссылок нет). Список всех застройщиков — `/admin/preview/zastrojshhik`.
У каждой страницы внизу справа кнопка **«Чек-лист данных»** — тот же список, но
посчитанный на лету для конкретного застройщика.

Обозначения: ✅ есть в базе · 🔧 выводится из других полей · 🟡 частично · ❌ нет в базе.

> **Картинки берутся только из Supabase Storage.** Вложения Airtable, которые всё ещё
> лежат в `data` (`Фотографии`, `Главное фото`, `Logo`, `Social:Image`), — мёртвые
> ссылки: `v5.airtableusercontent.com` отдаёт **410 Gone**. Живые источники:
> `complex-photos/_manifest.json` (199 комплексов), `villa-photos/_manifest.json`
> (601 вилла) и колонка `raw_developers.logo_url`.

База на 2026-07-31: **114 застройщиков**, **197 комплексов**, **573 виллы-листинга**.

## 3. Цифры застройщика (`developer_stats`)

Дизайн хочет 4 крупных числа и 6 карточек. Чисел в базе **нет ни одного** —
всё лежит текстом-буллетами в пяти полях. Прототип вытаскивает их регулярками
(для Urban Escape распознаёт 6 из 6, для других может меньше).

| Поле дизайна | | Источник / что мешает |
|---|---|---|
| `years_on_market`, `portfolio_volume_usd` | 🔧 | парсится из «Репутация и опыт» (заполнено у 90/114) |
| `units_under_construction`, `units_renting` | 🔧 | из «Строительство и недвижимость» (90/114) |
| `team_size`, `builders_count` | 🔧 | из «Команда» (85/114) |
| `complexes_done`, `complexes_building` | 🔧 | из «Бизнес и сервисы» (88/114), иначе считаем по комплексам |
| `mgmt_company_type` (own / outsource) | 🟡 | есть текст «Собственная» (89/114), enum нет |
| `payment_plan` | ✅ | `raw_complexes.«Payment plan,%»` — 138/197 (70%), но лежит **на комплексе**, а не на застройщике |
| `legal_entity`, `nib` | ❌ | юрлица и номера регистрации нет ни в одном поле |
| `financing` (свои / кредит) | ❌ | поля нет |

Карточки «Команда / Бизнес / Строительство / Репутация / Управляющая компания»
рендерятся **как есть** и выглядят ровно как в макете — это самая дешёвая часть.
Шестая карточка «Юридика и финансы» пустая целиком.

## Что добавить в Supabase, по приоритету

**1. Блокирует блоки целиком**
- Контакты застройщика: `department`, `full_name`, `avatar`, `lead_form_id`.
- `sold_pct` / `occupancy_pct` (или архивные юниты со статусом «продан») — иначе блок сданного комплекса пустой.
- `legal_entity`, `nib`, `financing` — шестая карточка цифр.

**2. Ломает «пиксельность» макета**
- Довести фото комплексов до 5+ (сейчас 43%) — иначе hover-слайдшоу и галерея вырождаются.
- Свой hero-кадр застройщика: сейчас 24 компании показывают подложку с инициалами, ещё 44 — логотип.
- Квартал сдачи вместо года.
- Номер разрешения (PBG) и срок продления лизхолда.

**3. Убирает костыли**
- Числовые колонки застройщика вместо парсинга буллетов (6 чисел).
- `tagline` — короткий слоган, отдельно от `SEO:Description`.
- `hq_address`, `founder` — вытащить из текста AI-описания в поля.
- Починить связь вилла→комплекс по id.
- Раскатать `nearby_places` на комплексы (сейчас 56%, файлы лежат по id виллы).
